# Retain Vanished Subagents (Cache Carryover)

## Design

**Проблема.** При переносе/перезапуске сессии со сменой cwd Claude Code переносит `<sid>.jsonl` между project-папками, но файлы агентов `subagents/agent-*.jsonl` при этом теряются. Инцидент 2026-09-05, сессия `31a67402`: за ворктри-фазу выполнено 9 Agent-вызовов (Tasks 1–8 + ретрай Task 7); после перезапуска «без ворктри» на диске во всём `~/.claude/projects` остались файлы только 2 агентов (Task 7 ретрай, Task 8) — Tasks 1–6 и первая попытка Task 7 удалены CC (проверено поиском всех `agent-*.jsonl` по mtime за окно инцидента: совпадений нет). Прежний фикс «поиск логов во всех папках» (`find_session_dirs` + merge, план 20260826-merge-subagents-across-session-dirs) здесь не помогает: глоб не может найти файлы, которых нет.

Усугубляющий фактор — наш кеш. `_compute_agents` строит список строго со диска, `_write_agents_cache` перезаписывает `data/agents_<sid>.json` ровно результатом скана. Первый же рендер после исчезновения файлов выкидывает агентов и из таблицы, и из кеша — хотя на тот момент кеш содержал их полные снапшоты (токены, время, описание, toolUseId). Т.е. данные у нас БЫЛИ — и мы их сами стёрли.

**Решение.** Кеш становится носителем истории сессии: агенты, чьи файлы исчезли из ВСЕХ просканированных session dirs, переносятся из кеша в вывод с последним известным состоянием.

1. **Carryover в `_compute_agents`** (после дискового скана, ДО queue-override): для каждого `agent_id` из кеша, отсутствующего в `seen_agent_ids` и с валидным dict-входом, добавить `{**entry, "agentId": agent_id}`. Статус `run` (и отсутствующий статус — `entry.get("status") in (None, "run")`) замораживается в новый `lost`: файлы исчезли, агент физически не может работать, а «живой» `run` тянул бы за собой `life_end = now` в `_agent_time_segments` — время агента росло бы вечно. Терминальные `ok/err/stop/kill` переносятся как есть. При заморозке в `lost` закрывается и открытый вопрос: `qa_open_ts` сворачивается в закрытую паузу `[qa_open_ts, ts_last]` (при `ts_last > qa_open_ts`) с обнулением `qa_open_ts` — иначе ветка `qa_open_ts > 0.0` в `_agent_time_segments` стоит РАНЬШЕ проверки статуса, и колонка wait росла бы вечно (`now − qa_open_ts` без капа).
2. **`_STATUSES` + `"lost"`** — рендер `[lost]` через существующий механизм иконок (`icon = f"[{status}]" if status in _STATUSES else "[?]"`); `[lost]` — 6 символов, ровно `_ICON_COL_WIDTH`, паддинг универсален (обновить комментарий у константы).
3. **Без изменений в остальном конвейере** (проверено по коду):
   - queue-override: guard `not in ("err", "stop")` — `lost` перезаписываем, реальный исход из `task_notifications` главного jsonl выигрывает;
   - `_agent_time_segments`: `status != "run"` и `qa_open_ts == 0` → `life_end = ts_last` — длительности заморожены (для этого carryover и закрывает открытый вопрос, см. п.1);
   - `sort_agents`: `toolUseId` из кеша → позиция из `tool_use_positions` главного jsonl — призраки встают на исторические места (fallback `mtime_meta` тоже в кеше);
   - `sum:`/per-model агрегаты считают перенесённые токены — история расходов сохраняется;
   - round-trip кеша: перенесённый агент записывается `_write_agents_cache`-ом обратно (все `_AGENT_CACHE_FIELDS` у него уже есть) — стабилен между рендерами.
4. **Возврат файла на диск** (CC вернул директорию): свежий скан перезапишет призрака — mtime/uuid изменившегося файла не совпадут с кеш-ключом, произойдёт re-scan. Краевой случай «файл вернулся с идентичными mtime+last_uuid» (mv сохраняет mtime): cache-hit вернёт запись с `lost` — приемлемо, агент действительно останавливался.
5. **Оркестраторный гейт `if session_dirs:`** (`_main_unsafe`, ~2997) не трогаем: если исчезли вообще все session dirs сессии (а main jsonl ещё находится), carryover не вызывается и призраки не показываются — кеш при этом не перезаписывается (write тоже под гейтом), т.е. деградация без потери данных. Unit-контракт `_compute_agents` меняется: «empty list → []» становится «empty list → только перенесённые из кеша» (докстринг обновить).

**Отвергнутые альтернативы:**

- _Реконструкция из главного jsonl по Agent tool_use блокам_ — в main-транскрипте нет per-agent usage; получились бы строки без токенов и времени. Ценность низкая, половинчатое решение.
- _Заморозка `run` в существующий `stop`_ — без нового слова в словаре статусов, но `stop` семантически значит «остановлен пользователем» (`stoppedByUser`); для «файлы пропали, исход неизвестен» это ложь. `[lost]` честнее и читается с первого взгляда. Выбор подтверждён пользователем.
- _Ничего не делать, задокументировать поведение CC_ — не сохраняет данные, которые мы уже держали в кеше.

**Видимое изменение:** строки агентов живут дольше своих файлов. Для сессий, где CC ничего не терял, поведение неотличимо (на диске есть файлы → carryover не срабатывает).

**Известные ограничения (зафиксировать в доке):**

- Призраки не экспирятся — живут в кеше/таблице всё время жизни сессии. Если CC начнёт рутинно чистить файлы агентов, строки будут накапливаться. Осознанный trade-off (инцидент показал обратное: терять данные дороже).
- `status_rev` на призраках не действует: bump ревизии пересканирует файлы на диске, но призрак пересканировать нечем — его статус живёт с момента заморозки.
- Директорная деградация: сессия без единого session dir не показывает призраков (см. Design п.5).

## Solution Overview

Кеш `data/agents_<sid>.json` из «зеркала диска» становится «диск + история»: агенты без файлов на диске переносятся в вывод и обратно в кеш с последним известным состоянием; статус `run` замораживается в `lost`. Все нижележащие механизмы (сортировка, время, override, sum) уже корректно работают с полями кеша — кодовых изменений в них нет.

## Technical Details

- Carryover-блок (псевдокод, в `_compute_agents` после цикла по директориям):
  ```python
  for agent_id, entry in agents_cache.items():
      if agent_id in seen_agent_ids or not isinstance(entry, dict):
          continue
      carried = {**entry, "agentId": agent_id}
      if carried.get("status") in (None, "run"):
          carried["status"] = "lost"
          # закрыть открытый вопрос, иначе wait растёт вечно
          # (_agent_time_segments проверяет qa_open_ts РАНЬШЕ статуса)
          qa_open = _to_float(carried.get("qa_open_ts")) or 0.0
          ts_last = _to_float(carried.get("ts_last")) or 0.0
          if qa_open > 0.0:
              if ts_last > qa_open:
                  pauses = carried.get("qa_pauses")
                  if isinstance(pauses, list):
                      pauses.append([qa_open, ts_last])
              carried["qa_open_ts"] = 0.0
      agents.append(carried)
  ```
- `_STATUSES = ("ok", "run", "err", "stop", "kill", "lost")`.
- Порченые записи (не dict) пропускаются; запись без полей рендерится через существующие деградации (`_to_int`, `.get`).
- Дедупликация с диском — по `seen_agent_ids` (тот же ключ, что и междиректорный дедуп).
